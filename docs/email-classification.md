# FengMail 邮件四级分类体系

> 文中的发件人、公司、平台均为占位示例，不是真实通信记录。
> 核心区分轴：**人发 vs AI发 vs 机器发**。只有真人在跟你对话的邮件才需要你亲自看。

---

## 核心原则

```
真正需要你看的 = 真人发的 + 需要你做事
自动发的邮件  = 都不需要研究，只是通知级别不同
```

**三种发送者类型：**

| 标识 | 类型 | 判断方法 |
|------|------|----------|
| 👤 | **人发** | 发件人是真人的个人邮箱/公司邮箱（非 noreply），邮件内容有明显人工撰写痕迹 |
| 🤖 | **AI发** | 发件人是真人邮箱，但正文明显是 AI 生成/模板化（招聘平台代发、AI agent 发出） |
| ⚙️ | **机器发** | noreply 地址、平台自动通知、系统触发的纯模板邮件 |

---

## 四级定义

### 🔴 L1 — 👤 人发 · 需行动

**特征**：真人写了邮件给你，且需要你回复/决定/操作。

| 场景 | 识别线索 | 真实示例 |
|------|----------|----------|
| **面试邀请（真人写的）** | 发件人 @公司域名，个人署名，非模板 | 【已脱敏】 — Interview Invitation for Sales Executive |
| **直接招聘 / 挖人** | 真人 HR 直接发邮件，无平台转发 | <recruiter> @<company>.com — AI Interview 提醒 |
| **需要回复的对话** | 有来有回，不是单向通知 | 某公司对话（account3） |
| **熟人 / 同事私信** | 实名个人邮箱发来 | 【已脱敏】 (【已脱敏】) — Summer Internship |
| **LinkedIn 真人请求** | 有真实姓名的邀请 | 【已脱敏】 |

**响应**：立即通知用户，提供正文摘要 + 建议操作。

---

### 🟡 L2 — 👤 人发 · 仅告知

**特征**：真人发了消息，但只是通知性质，不需要你做什么。

| 场景 | 识别线索 |
|------|----------|
| **不需要回复的通知** | 看完即可 |
| **已经过时的对话** | 事情已经结束了 |

**响应**：在报告中列出，询问是否要读正文。

---

### 🔵 L3 — 🤖/⚙️ 较重要自动通知

**特征**：机器 / AI 发的，但内容有实际意义，需要你知道。

| 场景 | 识别线索 | 示例 |
|------|----------|------|
| **API / 服务申请结果** | 涉及服务开通/被拒 | Webull OpenAPI 申请未通过 |
| **账户安全警告** | 安全相关，需确认是否本人操作 | OpenRouter 新设备登录、Google 安全提醒 |
| **面试反馈（招聘系统）** | 面试后的正式反馈 | 某公司面试反馈问卷 |
| **求职状态关键更新** | 明确的状态变化 | 某公司申请状态更新 |

**响应**：在报告中列出标题，一句话说明影响，不展开正文。

---

### ⚪ L4 — ⚙️ 一般自动通知

**特征**：纯系统自动流水线，不需要人看。只需在报告里给出数量统计。

| 场景 | 识别线索 | 示例 |
|------|----------|------|
| **🐶 保险狗** | 保险公司域名（yflife 等），"Financial Planner" 等保险岗 | EY Secretary @yflife.com.hk — 看起来像面试，实际是保险销售招募 |
| **求职平台自动回复** | @broadbean.net noreply，"Re: XXXX/SEEK/姓名/P" 格式的自动通知，收到 recruiter 查看申请时触发，不是真回复 | 【已脱敏】、【已脱敏】、【已脱敏】、【已脱敏】 等全系列 |
| **招聘平台投递确认** | Workable、Greenhouse 自动确认 | 示例公司 A / B / C 申请确认 |
| **证券交易所通知** | 券商系统自动通知、月结单 | <券商> Service <service@broker.example> |
| **加密货币交易所** | OKX、HashKey Exchange 等交易平台通知 | OKX <updates@okx.com> |
| **工具/平台更新通知** | Ollama、OpenRouter、Docker、Trae、AlfredCamera 等更新邮件 | Ollama <hello@ollama.com> |
| **游戏平台** | Epic Games 等游戏通知 | Epic Games <help@acct.epicgames.com> |
| **域名/注册商** | GNAME、Cloudflare 域名管理通知 | GNAME <noreply@share-dns.net> |
| **面试体验调查** | 招聘系统的自动问卷 | 某公司面试反馈问卷 |
| **证券平台系统通知** | [登入系统]、[执行交易]、Asset Daily Statement | Webull 大量重复通知 |
| **订单 / 收据** | 平台自动开具 | McDonald's、Epic Games |
| **学校 / 机构周报** | 批量发送的 newsletter | <机构> Career Center weekly |
| **账号 / 授权通知** | Google/Microsoft 数据共享通知 | Google shared data with Groq/Claude |
| **QQ Agent 测试邮件** | user1@example.com | [申请助手] 系列测试 |
| **银行通知** | 银行系统通知 | <银行> Mobile App |
| **积分 / 奖励** | Microsoft Rewards、club1933 | 九巴俱乐部 |
| **猎头平台代发** | TeamTailor 等自动确认 | Dayuse (【已脱敏】 — 实际上是系统自动发) |
| **🏚️ 空壳招聘公司** | 公司网上搜不到产品/业务/官网，只有招聘页面 | <公司 A> → <公司 B>（改名过的公司，注册信息只有招聘） |

**🏚️ 空壳招聘公司判断标准**：
1. 搜公司名只有公司注册信息和招聘页面
2. 没有官网（或官网打不开/无内容）
3. 没有实际产品或业务描述
4. 曾改过名（从 A 改到 B，旧名搜不到任何业务记录）
5. 符合以上任意 2 条的 → L4 直接标已读

**🐶 保险狗地区模式**：以下几个特征是 100% 保险销售招募的信号，任意组合出现即为 L4：
- **利园一期（Lee Garden One, 33 Hysan Avenue, Causeway Bay）** — 保险/财富管理公司在此租虚拟办公室做 recruitment 的重灾区
- **邮件来自 gmail.com 猎头**（非公司域名），标题含 "Management Trainee"
- 类似的铜锣湾/湾仔金融区写字楼（如 Tower 535、Times Square 附近）
- 要求带身份证明 + 学历证书去面试
- 提到 "wealth management / private banking / 财富管理 / 理财顾问"
- 结合以上地区的 "Management Trainee" → 直接按保险狗处理

**响应**：在报告底部按类别统计计数，一行带过。

## 快速区分技巧

### 怎么看是不是「人发」

| 特征 | 👤 人发 | ⚙️ 机器发 |
|------|---------|-----------|
| 发件人地址 | `name@公司.com`（有真名） | `noreply@...`、`notification@...` |
| 回复地址 | 可以回复到真人 | Return-Path 是 bounce 地址 |
| 内容 | 有个性化措辞、上下文引用 | 模板化、固定句式 |
| 触发模式 | 事件驱动（真人做了某事触发的单次行为） | 批量发送、时间驱动 |

### 常见误判

- **Broadbean / SEEK 回复**（"Re: XXXX/SEEK/姓名/P"）→ ⚙️ 机器发。noreply 地址，"Re:" 看起来像回复，实际是平台自动当 recruiter 查看了你的申请时触发
- **"has responded to your application" via Jobsdb** → ⚙️ 机器发。平台模板消息，不是真人写的
- **"New Invite" from OneForma** → 🤖 AI发。可能是 AI 辅助 recruitment
- **LinkedIn 连接请求** → 👤 人发（有真实身份的人发的）

## 报告格式

```
## 📬 [日期] 邮件日报

### 🔴 需处理（N 封）
- [邮箱] [发件人] [标题] — 一句话说明

### 🟡 仅告知（N 封）
- [邮箱] [发件人] [标题]

### 🔵 重要通知（N 封）
- [邮箱] [标题] — 说明

### ⚪ 自动通知（汇总）
- [邮箱] Webull 系统 x3、Broadbean 自动回复 x2、收据 x1…
```

---

## 特殊规则

1. **同一条通知多账号收到** → 只报告一次，标注 "已另发至 XX 邮箱"
2. **同一对话多封（如同一个 SEEK 职位的多次平台触发）** → 合并计数
3. **已读但未处理** → 下次报告仍提示
4. **深夜/周末邮件** → 时间标注在标题后
